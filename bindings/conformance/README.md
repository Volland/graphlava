# Binding conformance corpus

[graphlava](https://graphlava.org) runs in Rust, C, Python, Node.js, Swift and Kotlin ([bindings overview](../README.md)); this corpus is how they stay one database. It is the language-neutral contract every binding runs ([ADR 0042](../../docs/adr/0042-binding-strategy.md)). It adds the host-mapping edge cases that the oracle traces do not generate: the ±2^57 inline limit, ±2^63, `2**70`, NaN and infinities, naive and aware datetimes, decimal scale, empty results and 64-deep graph nesting.

- `schema.json`: JSON Schema of one record (draft 2020-12).
- `*.jsonl`: one case per line. Every `id` is unique across all files. Files are grouped by owner: `core.jsonl` (shared cases, generated by `gen_core.py`) and one file per binding for its host-only cases (for example `node.jsonl`).
- Runner order: the Rust runner (`crates/graphlava/tests/conformance.rs`, `cargo test -p graphlava --test conformance`) validates every case against the schema rules and executes the cases whose `hosts` include `*` or `rust`. A corpus bug therefore fails in Rust first and is not reported as a binding bug. Each binding then runs the cases whose `hosts` include `*` or its own name.

## Running a case

Each case gets a fresh database file in a temp directory. Default prefix for IRIs is `http://ex.org/`.

| `kind` | Steps | Pass when |
| --- | --- | --- |
| `roundtrip` | Insert `(ex:s, ex:p, value)` as one `ordered` one-shot submit. If `reopen`, close and reopen the file. Read `out(ex:s, ex:p)` and decode the object. | The decoded term equals `expect.term` (default `value.term`); the host value converted from it equals `expect.native` (default `value.native`); if `inline` is given, bit 63 of the object ID matches it. |
| `reject` | Build the host value from `value.native` and insert it as in `roundtrip`. | The binding raises `error` before any write; the file has no statement. The Rust runner only validates these (host-level rules such as "NaN is rejected" have no Rust equivalent). |
| `query` | Run `setup` ops, then `text` in `lang` on a fresh snapshot. | `expect.vars` equals the projected variables and `expect.rows` equals the rows (as a multiset unless `ordered`), or `expect.boolean` / `expect.count` match. |
| `ops` | Run `ops` in order. | Every op with `error` fails with that error and changes nothing; every other op succeeds and, when `result` is given, returns it. |

Each op runs as its own one-shot `submit` with `ordered` durability, so a failing op does not undo earlier ones. `"op": "reopen"` closes and reopens the file. An op's `as` binds its resulting ID (statement, graph or hyperedge) to a name; later ops refer to it with `"id": "<name>"` or the term `{"ref": "<name>"}`.

## Terms and values

- Term: `{"iri": "..."}`, `{"bnode": "label"}`, `{"literal": "lex", "datatype": "...", "lang": "..."}` (datatype defaults to `xsd:string`), `{"triple": [s, p, o]}`, or `{"ref": "name"}`.
- Value: `{"term": Term, "native": {"type": ..., "value": ...}}`. A host builds its value from `native` when it knows the type, and from `term` otherwise. Native types: `int` (decimal string of any size), `float` (`"NaN"`, `"INF"`, `"-INF"`, `"-0.0"` or a decimal), `bool`, `str`, `decimal` (lexical, scale kept), `datetime` (ISO 8601 with offset), `naive_datetime` (no offset), `date`. Bindings may add host-specific types (for example `node`: `safe_number`, `date_ms`); other hosts skip them.
- Errors are Rust `Error` variant names (`Invalid`, `Conflict`, `FillsRole`, ...). Python maps each to `<Name>Error`, Node to an error code, Swift and Kotlin to their enum case.

## Adding cases

Append lines to your binding's file; keep `id` unique and kebab-case with a file prefix (`py-`, `node-`, ...). Run `cargo test -p graphlava --test conformance` before the binding's own runner. `core.jsonl` is regenerated with `python3 bindings/conformance/gen_core.py`; edit the generator, not the file.
